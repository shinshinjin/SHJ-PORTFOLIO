푸하하월드

여러 명이 한 마을에 접속해 함께 플레이하는 브라우저 3D 게임입니다. 기획부터 클라이언트, 서버, 배포까지 혼자 만들고 있습니다.

형태
개인 프로젝트
기간
2026.11–
플랫폼
웹 (데스크톱·모바일)
기술
Three.js, Cloudflare Workers·Durable Objects, D1

프로젝트 소개

캐릭터를 꾸며 마을에 들어가면 다른 플레이어와 함께 몬스터를 잡고, 낚시를 하고, 콩(게임 화폐)으로 장비와 옷을 살 수 있습니다. 집 구매, 파티, PC방 지뢰찾기 기능도 있습니다.

콩과 아이템을 서버에서만 바꿀 수 있게 하는 작업과, 기능을 고칠 때마다 자동으로 테스트하는 과정에 시간을 많이 썼습니다.

Claude Code를 함께 사용해 개발했습니다. 기능과 구조는 직접 정했고, 결과는 테스트와 실제 화면으로 확인했습니다.

서버가 판정하는
구조

처음에는 콩과 가방을 클라이언트가 저장해서, 브라우저 콘솔로 값을 바꿀 수 있었습니다. 그래서 콩·가방·레벨·보상은 서버만 바꾸도록 구조를 바꿨습니다. 클라이언트는 구매·판매 같은 요청만 보내고, 서버가 가격·거리·하루 횟수를 확인한 뒤 결과를 돌려줍니다.

클라이언트 요청→방 (GameRoom)→계정 (Player) 검사→D1 저장→결과

방 하나 = 서버 객체 하나

Cloudflare Durable Objects로 방마다 객체를 하나씩 둡니다. 계정마다 Player 객체가 있어서, 같은 계정으로 다시 접속하면 이전 연결을 끊습니다. 공개 서버는 Lobby가 자동으로 고르고, 비공개 방은 6자리 코드로 들어갑니다.

몬스터도 서버가 움직임

몬스터의 이동·공격·피격은 서버가 계산합니다. 타이머를 두지 않고 메시지가 올 때 지난 시간만큼 진행해서, 아무도 없는 방은 Hibernation 상태로 쉬고 비용이 들지 않습니다.

보내는 메시지도 검사

메시지 크기·초당 개수·형식을 확인해 한도를 넘는 메시지는 버리고, 계속 넘으면 연결을 끊습니다. 플레이어 id와 채팅 이름은 서버가 붙여서 다른 플레이어로 위장할 수 없습니다.

넓은 월드와
성능

월드는 반경 1500m입니다. 80m 칸으로 나눠 플레이어 주변 칸만 만들고, 멀어지면 지웁니다. 칸 좌표로 난수를 정해서 같은 칸은 언제 만들어도 같은 모양입니다.

성능은 비교 장면 8개를 정해 두고, 작업 전후로 드로우콜·삼각형 수·메모리를 재면서 고쳤습니다. 그래픽 품질 단계(낮음·보통·높음·자동)를 만들고 움직이지 않는 건물 메시를 재질별로 합쳐, 마을 장면 드로우콜을 높음 기준 1,734에서 1,360으로, 낮음 기준 607에서 493으로 줄였습니다. 몬스터 모델이 GPU에서 해제되지 않던 메모리 누수도 고쳤습니다.

테스트와 배포

규칙과 서버는 Vitest(Cloudflare 실행 환경 + 로컬 DB)로, 화면 흐름은 헤드리스 Chrome 스모크 테스트로 확인합니다. 2026년 11월 기준 테스트 284개, 스모크 항목 41개입니다.

dev 브랜치→Pull Request→테스트→main 병합→자동 배포

직접 배포하지 않고, main에 합쳐지면 GitHub Actions가 테스트를 다시 실행해 통과했을 때만 Cloudflare에 배포합니다. 타입 검사(JSDoc + TypeScript)와 린트(Biome)도 이 단계에서 함께 확인합니다.

미니게임

PC방 컴퓨터에서 지뢰찾기를 할 수 있습니다. 이기면 콩을 받기 때문에 지뢰 위치는 서버에만 두고, 칸을 열 때마다 서버가 결과를 알려 주도록 만들었습니다.
