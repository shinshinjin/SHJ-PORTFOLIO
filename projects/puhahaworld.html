푸하하월드

여러 명이 한 월드에 접속해 함께 노는 브라우저 3D 게임입니다. 기획, 클라이언트, 서버, 배포를 혼자 맡고 있고 지금도 매일 고치고 있습니다.

프로젝트 소개

캐릭터를 꾸며 들어가면 다른 플레이어와 함께 몬스터를 잡고, 낚시를 하고, 집을 사서 꾸밉니다. 반경 1.5km 월드에 지역 13곳과 마을 12곳이 있고, 씨앗돌 순간이동·버스·배로 이동합니다.

몬스터 50종의 모형은 Blender 스크립트로 만들고, 소리는 음원 파일 없이 Web Audio로 합성합니다. 결과가 남는 값(콩·아이템·경험치·HP)은 모두 서버가 계산합니다.

2026.11.10 기준 커밋 234개, 자동 테스트 780개, 화면 스모크 72항목, 개발 기록 문서 90개. Claude Code와 함께 개발하고 있습니다. 무엇을 넣을지와 구조는 제가 정하고, 결과는 테스트와 직접 플레이해서 확인합니다.

업데이트 기록

최근 작업부터 적었습니다. 항목마다 저장소에 개발 기록 문서와 테스트가 있습니다.

  1. 11.09지하 동굴월드

    지형을 실제로 파낸 동굴 2곳(새싹 지하 통로, 수정 지하 동굴)을 만들었습니다. 동굴 안에서는 바닥·천장·벽 충돌과 카메라가 동굴을 따라가고, 입구는 지도에 표시됩니다. 바위 협곡 지역도 하나 늘렸습니다.

  2. 11.09보스 공격 패턴전투

    같은 공격을 두 번 연달아 쓰지 않고, 등급이 높을수록 연속 공격이 길어집니다. HP가 50% 아래로 내려가면 예고 시간과 대기 시간이 짧아집니다. 화면에 보이는 공격 예고도 서버와 같은 식으로 계산해 어긋나지 않습니다.

  3. 11.09요청 위조 막기보안

    접속 직후 서버가 아직 위치를 모를 때 보낸 요청이 거리 검사를 그냥 통과하던 구멍을 막았습니다. 옛 프로토콜 버전을 보낸 연결은 공격과 경제 요청을 못 합니다. 계정 요청은 복사본에서 처리하고 성공했을 때만 반영해, 동시에 보내도 콩이 늘거나 사라지지 않습니다.

  4. 11.09스토리와 주민콘텐츠

    스토리 1~2장, 주민 호감도, 감정 표현 8종을 넣었습니다. 호감도가 80 이상인 주민은 따라다니며 성격마다 보너스를 하나 줍니다. 보상과 보너스는 서버가 판정합니다.

  5. 11.08무기 등급과 토벌 의뢰밸런스

    몬스터가 떨어뜨리는 무기 23종에 6단계 등급을 붙이고, 하루 토벌 의뢰, 몬스터 도감, 칭호를 넣었습니다.

  6. 11.08파티 사냥 보상밸런스

    근처 파티원이 경험치를 각자 받도록 바꿨습니다. 혼자 100%, 2명 80%, 3명 70%, 4명 60%. 예전에는 데미지 비율로 나눠 4명이면 25%씩이라 파티가 손해였습니다.

  7. 11.08레벨 곡선을 목표 시간에서 계산밸런스

    "lv70까지 한 달(약 115시간)"이라는 목표에서 레벨별 시간을 정하고, 사냥 효율로 필요 경험치를 계산합니다. 몬스터에 레벨 1~90을 붙이고, 근력을 더하기에서 배율로 바꿔 무기가 다시 의미 있게 했습니다.

  8. 11.08벽 뚫림 수정물리

    빠른 탈것 + 느린 기기에서 벽 181곳 중 131곳을 뚫던 문제를, 이동을 0.25m 조각으로 나눠 0곳으로 만들었습니다.

  9. 11.08치팅 방지 6단계보안

    낚시 타이밍, 이동 속도, 데미지 상한, 서버 HP, 공격 속도를 서버가 검사하고, 의심 계정은 끊고 기록해 관리자 화면에서 봅니다. 보안 헤더(CSP)와 의존성 검사도 CI에 넣었습니다.

  10. 11.08그래픽 최적화 2차렌더링

    마을 장면 드로우콜 1,505 → 1,158, 삼각형 약 45% 감소. 움직이는 부분을 잘못 합치지 않았는지 자동으로 잡는 검사를 함께 만들었습니다.

  11. 11.07소리, 탈것, 집 꾸미기콘텐츠

    효과음 18종·배경음악 9곡·말소리 4종을 합성으로 만들고, 탈것 4종과 가구 배치·보관함·4층 집을 넣었습니다.

  12. 11.07몬스터 46종 Blender 모형모델링

    Blender 스크립트로 모형을 만들고 부품을 합쳐 한 마리 드로우콜을 약 39에서 11로 줄였습니다. 얼굴은 3D 눈 대신 그림으로 붙입니다.

  13. 11.06경제를 서버로서버

    콩·가방·레벨을 계정마다 하나인 서버 객체(Player)가 관리하도록 옮겼습니다.

  14. 11.04첫 커밋시작

    Cloudflare Workers + Durable Objects 위에 방 하나짜리 3D 마을로 시작했습니다.

다음 작업: 스토리 3장(버섯 골짜기와 새싹 지하 통로).

서버가 판정하는 구조

처음에는 콩과 가방을 클라이언트가 저장해서 브라우저 콘솔로 값을 바꿀 수 있었습니다. 지금은 클라이언트가 요청만 보내고, 방(GameRoom)과 계정(Player) 서버 객체가 확인한 뒤 결과를 돌려줍니다.

방 하나 = 서버 객체 하나

방마다 Durable Object를 하나 두고, 계정마다 Player 객체가 있어 같은 계정으로 다시 접속하면 이전 연결을 끊습니다. 공개 서버는 Lobby가 고르고, 비공개 방은 6자리 코드로 들어갑니다.

타이머 없는 몬스터

몬스터 이동·공격·피격은 서버가 계산합니다. 메시지가 올 때 지난 시간만큼 진행해서, 아무도 없는 방은 Hibernation으로 쉬고 비용이 들지 않습니다.

정상 플레이가 먼저

치팅 판정 기준은 평범하게 플레이하는 사람이 걸리지 않도록 넉넉하게 잡았습니다. 예를 들어 서버 HP는 가진 장비 중 가장 좋은 방어를 기준으로 계산해, 서버 HP가 화면 HP보다 먼저 0이 되지 않습니다.

서버 검사 항목. 기준을 넘으면 그 요청은 버리고, 짧은 시간에 여러 번이면 연결을 끊고 기록합니다.

넓은 월드와 성능

월드는 80m 칸으로 나눠 플레이어 주변 5×5칸만 만들고, 멀어지면 지웁니다. 칸 좌표로 난수를 정해 같은 칸은 언제 만들어도 같은 모양입니다.

성능은 고정 장면 8개를 정해 두고 작업 전후로 같은 조건에서 쟀습니다. 품질 단계(낮음·보통·높음·자동), 움직이지 않는 메시 합치기, 외곽선 거리 컬링, 나무 그림자 대역을 넣었습니다.

그래픽 1차 최적화 전후 (높음 품질, 헤드리스 Chrome 소프트웨어 렌더링이라 프레임 ms는 비교용)

벽 뚫림 수정

플레이어 이동은 한 프레임 이동 거리만큼 옮긴 뒤 벽 밖으로 밀어내는 방식입니다. 한 번에 많이 움직이면 벽 중심선을 넘어 반대편으로 밀려납니다. 무당벌레 탈것 + 초당 20프레임이면 한 프레임에 0.86m를 움직여 벽을 뚫었습니다.

레벨 곡선

처음 점검해 보니 쉬지 않고 사냥하면 약 10시간에 최고 레벨(90)이었습니다. 근력 스탯이 공격력에 그대로 더해져 lv30이면 +145인데, 가장 센 무기는 10이었습니다.

그래서 경험치 표를 감으로 정하지 않고 목표 시간에서 거꾸로 계산하게 바꿨습니다. lv70까지 실제 플레이 약 115시간, lv90까지 약 465시간을 목표로 레벨마다 머무는 시간을 정하고, 그 시간 동안 제 레벨 몬스터를 잡아 얻는 경험치를 필요 경험치로 씁니다.

모바일

휴대폰은 가로 화면으로 조이스틱과 버튼을 씁니다. 버튼은 44px 이상으로 맞추고, 노치를 피하고, 미니맵을 누르면 지도가 열리게 했습니다. 휴대폰에서는 공격할 때 가까운 몬스터 쪽으로 몸을 돌리는 보조를 기본으로 켭니다.

테스트와 배포

규칙과 서버는 Vitest(Cloudflare 실행 환경 + 로컬 DB)로, 화면 흐름은 헤드리스 Chrome 스모크로 확인합니다. 2026.11.10 기준 테스트 780개, 스모크 72항목입니다. 스모크에는 벽 뚫림, CSP 위반, 메시가 잘못 합쳐진 애니메이션처럼 화면에서 잘 안 보이는 문제를 잡는 항목도 있습니다.

dev 브랜치→Pull Request→문법·린트·타입·테스트·npm audit→main 병합→자동 배포

직접 배포하지 않습니다. main에 합쳐지면 GitHub Actions가 검사를 다시 실행하고, 통과했을 때만 D1 마이그레이션 후 Cloudflare에 배포합니다.
