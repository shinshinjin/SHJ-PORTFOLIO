푸하하월드

웹 브라우저에서 여러 명이 한 마을에 접속해 함께 노는 3D 게임입니다. 기획, 클라이언트, 서버, 테스트와 배포까지 혼자 만들고 있습니다.

형태
개인 프로젝트
기간
2026.11–
플랫폼
웹 (데스크톱·모바일)
기술
Three.js, Cloudflare Workers·Durable Objects, D1

프로젝트 소개

캐릭터를 꾸며 마을에 들어가면 다른 사람과 같은 월드에서 몬스터를 잡고, 낚시를 하고, 콩(게임 화폐)으로 장비와 옷을 사고, 집을 살 수 있습니다. 파티를 맺어 쓰러진 친구를 일으키거나 PC방에서 지뢰찾기를 할 수도 있습니다.

게임을 만드는 것만큼 "여러 사람이 동시에 접속해도 속일 수 없고, 비용이 적게 드는 서버"와 "고쳐도 깨지지 않게 확인하는 과정"에 시간을 들였습니다.

AI 코딩 도구(Claude Code)와 함께 만들었습니다. 무엇을 만들지와 구조는 직접 정하고, 결과는 테스트와 화면 확인으로 검증했습니다.

서버가 판정하는
구조

처음에는 클라이언트가 콩과 가방을 직접 저장했는데, 이러면 브라우저 콘솔에서 숫자를 바꿀 수 있습니다. 그래서 콩·가방·레벨·보상을 바꾸는 일은 모두 서버가 하도록 바꿨습니다. 클라이언트는 "이걸 사고 싶다" 같은 요청만 보내고, 서버가 가격·거리·하루 횟수를 검사한 뒤 결과를 돌려줍니다.

클라이언트 요청→방 (GameRoom)→계정 (Player) 검사→D1 저장→결과

방 하나 = 서버 객체 하나

Cloudflare Durable Objects로 방마다 객체를 하나씩 둡니다. 계정마다 객체(Player)가 따로 있어 같은 계정으로 두 번 접속하면 먼저 연결을 끊습니다. 서버 목록(Lobby)은 공개 서버를 자동으로 고르고, 비공개 방은 6자리 코드로 들어갑니다.

몬스터도 서버가 움직임

몬스터의 이동·공격·피격을 서버가 계산합니다. 타이머 없이 메시지가 올 때 지난 시간만큼 진행하기 때문에, 아무도 없는 방은 잠들어(Hibernation) 비용이 들지 않습니다.

보내는 메시지도 검사

메시지 크기, 초당 개수, 형식을 검사해 넘치는 메시지는 버리고, 계속 넘치면 연결을 끊습니다. 플레이어 id와 채팅 이름은 서버가 붙여서 다른 사람인 척할 수 없습니다.

넓은 월드와
성능

월드는 반경 1500m이고, 80m 칸으로 나눠 내 주변 칸만 만들고 멀어지면 지웁니다. 같은 칸은 언제 만들어도 같은 모양이 되도록 칸 좌표로 난수를 정했습니다.

성능은 고정된 비교 장면 8개에서 드로우콜·삼각형 수·메모리를 작업 전후로 재며 고쳤습니다. 그래픽 품질 단계(낮음·보통·높음·자동)를 만들고, 움직이지 않는 건물 메시를 재질별로 합쳐 마을 장면 드로우콜을 높음 1,734에서 1,360으로, 낮음 607에서 493으로 줄였습니다. 장면을 오갈 때마다 몬스터 모델이 GPU에서 해제되지 않던 메모리 누수도 찾아 고쳤습니다.

테스트와 배포

기능을 바꿀 때마다 다른 곳이 깨지지 않았는지 자동으로 확인합니다. 규칙과 서버는 Vitest로(Cloudflare 실행 환경 + 로컬 DB), 실제 화면 흐름은 헤드리스 Chrome 스모크 테스트로 확인합니다. 2026년 11월 기준 테스트 284개, 스모크 항목 41개입니다.

dev 브랜치→Pull Request→테스트→main 병합→자동 배포

배포는 직접 하지 않습니다. main에 합쳐지면 GitHub Actions가 테스트를 다시 돌리고, 통과했을 때만 Cloudflare에 배포합니다. 타입 검사(JSDoc + TypeScript)와 린트(Biome)도 같은 단계에서 확인합니다.

미니게임

PC방 컴퓨터에서 지뢰찾기를 할 수 있습니다. 이기면 콩을 받기 때문에, 지뢰 위치는 서버 메모리에만 두고 칸을 열 때마다 서버에 물어보도록 만들었습니다. 브라우저에서 답을 미리 볼 수 없습니다.
